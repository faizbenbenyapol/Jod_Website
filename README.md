# จดกำไร — สมุดจดรายรับ–ต้นทุนรายวันสำหรับแม่ค้าตลาด

**ทดลองใช้งาน: https://jod.benyapol.com**

เว็บแอปที่ช่วยแม่ค้าตลาดนัดซึ่งซื้อวัตถุดิบวันต่อวัน ให้รู้ **กำไรจริง** ของแต่ละวัน
ปัญหาที่ตั้งใจแก้: เวลาเอาเงินที่ขายได้ลบต้นทุน มักลืมนับรายจ่ายแฝง เช่น แก๊ส ภาชนะ ค่าที่ น้ำแข็ง ทำให้กำไรที่คิดไว้สูงกว่าความจริง

ออกแบบเป็นเครื่องมือฝึกทักษะในโครงการ 6 สัปดาห์ (ผู้เข้าร่วม 60 คน ทีม 3 คน) จึงมี 2 ฝั่ง:

| ฝั่ง | ทำอะไรได้ |
|---|---|
| **แม่ค้า** (ใช้บนมือถือ) | จดยอดขายและต้นทุนของวัน → เห็นกำไรทันที · ระบบเตือนต้นทุนที่มักลืม และวันที่ลืมจด · ดูย้อนหลังรายเดือนพร้อมกราฟและค่าเฉลี่ยต่อวัน · กดขอให้ทีมช่วยได้โดยไม่ต้องพิมพ์ |
| **ทีมโครงการ** (หลังบ้าน) | เห็นว่าใครต้อง "โทรวันนี้ / ส่งข้อความเตือน / ปกติ" จากข้อมูลการจดอัตโนมัติ · รับเรื่องขอความช่วยเหลือและติดตามสถานะ |

หน้าแรกมีปุ่ม **"ทดลองเป็นแม่ค้า"** และ **"ทดลองเป็นทีมงานโครงการ"** พร้อมข้อมูลเดโม 60 ร้านย้อนหลัง 6 สัปดาห์ (ข้อมูลสมมติทั้งหมด)
ทดลองกดอะไรได้เต็มที่ แล้วกด **"รีเซ็ตข้อมูลเดโม"** ที่แถบด้านบนเพื่อกลับเป็นข้อมูลชุดแรก

## Technology stack

| ส่วน | ใช้อะไร | เหตุผล |
|---|---|---|
| Backend | Node.js (โมดูลมาตรฐานเท่านั้น ไม่มีไลบรารีภายนอก) | ต้นแบบเล็ก ไม่ต้องติดตั้งอะไรเพิ่ม |
| Frontend | HTML · CSS · JavaScript ล้วน (ไม่ใช้ framework) | หน้าเบา โหลดเร็วบนมือถือสเปกต่ำ |
| ข้อมูล | ไฟล์ JSON | พอสำหรับต้นแบบ แยกไว้ชั้นเดียว เปลี่ยนเป็นฐานข้อมูลจริงได้โดยไม่แตะส่วนอื่น |
| กราฟ | SVG ที่วาดเอง | ไม่ต้องพึ่งไลบรารีกราฟ |
| ฟอนต์ | Noto Sans Thai Looped (Google Fonts) | ฟอนต์ไทยแบบมีหัว อ่านง่ายสำหรับผู้ใช้สูงวัย |
| Deploy | Docker | รันได้เหมือนกันทุกเครื่อง |

## โครงสร้างโค้ด

```
src/
  logic.js     กติกาทางธุรกิจทั้งหมด: ตรวจข้อมูลที่กรอก, คำนวณกำไร, จัดการการจดซ้ำ,
               สรุปช่วงติดตาม 14 วัน, จัดลำดับว่าใครต้องติดตามก่อน
               — ไม่ยุ่งกับ HTTP หรือไฟล์ จึงแก้กติกา/ทดสอบได้ที่เดียว
  store.js     อ่าน–เขียนข้อมูล (ส่วนอื่นไม่ต้องรู้ว่าเก็บที่ไหน)
  server.js    เซิร์ฟเวอร์ HTTP: ส่งหน้าเว็บ + API

public/
  index.html, vendor.js   หน้าแม่ค้า: หน้าเข้าใช้งาน + 3 เมนู (จดวันนี้ / ดูย้อนหลัง / ขอให้ทีมช่วย)
  team.html, team.js      หน้าทีม: แท็บกรองตามความเร่งด่วน, ค้นหา, คิวคำขอความช่วยเหลือ
  ui.js                   ป๊อปอัปยืนยันและข้อความแจ้งเตือนของแอป (แทนกล่องของเบราว์เซอร์)
  demo.js                 ปุ่มรีเซ็ตข้อมูลเดโม
  style.css               ดีไซน์ทั้งหมด (ออกแบบจากมือถือก่อน แล้วขยายสำหรับ iPad และโน้ตบุ๊ก)

scripts/seed.js   สร้างข้อมูลเดโม 60 ร้าน (สมมติทั้งหมด)
test/             เทสต์อัตโนมัติ
docs/             ผลการทดสอบ และหลักฐานภาพก่อน–หลังแก้
```

### การไหลของข้อมูล
```
หน้าแม่ค้า ──จดยอด──▶ server.js ──ตรวจ/คำนวณ──▶ logic.js
                         │                         │
                         ▼                         ▼
                      store.js ◀────บันทึก──── ผ่านการตรวจ
                         │
หน้าทีม ◀──จัดลำดับ โทร/เตือน/ปกติ── logic.js ◀── อ่านข้อมูลทุกร้าน
```

### API

| Method | Path | หน้าที่ |
|---|---|---|
| GET | `/api/vendor/:id` | ข้อมูลหน้าแม่ค้า (บันทึกทั้งหมด, สรุป 14 วัน, คำขอที่ค้าง) |
| POST | `/api/vendor/:id/entries` | บันทึกยอดประจำวัน — ข้อมูลผิดตอบ 400, จดวันเดิมซ้ำตอบ 409 ให้เลือกบวกเพิ่ม/แทนที่ |
| POST | `/api/vendor/:id/help` | ส่งคำขอความช่วยเหลือ (กดซ้ำไม่สร้างใหม่) |
| GET | `/api/team` | รายชื่อเรียงตามความเร่งด่วน + คิวคำขอ |
| PATCH | `/api/help/:id` | เปลี่ยนสถานะคำขอ (รอรับเรื่อง → กำลังช่วย → เสร็จ) |
| POST | `/api/demo/reset` | รีเซ็ตเป็นข้อมูลเดโมชุดแรก (มีเฉพาะในต้นแบบ) |

## ข้อจำกัดของต้นแบบ
- ไม่มีระบบยืนยันตัวตน ใครมีลิงก์ก็เข้าได้ และปุ่มรีเซ็ตเดโมใช้ได้กับทุกคน (ระบบจริงต้องมีการยืนยันตัวตน และต้องเอาปุ่มรีเซ็ตออก)
- เก็บข้อมูลเป็นไฟล์เดียว เหมาะกับต้นแบบเท่านั้น
- รองรับเฉพาะร้านที่ซื้อวัตถุดิบรายวัน ยังไม่รองรับสต็อกที่ซื้อเป็นเดือน
